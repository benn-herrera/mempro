### 4.1 CLI command surface

Binary subcommands (see also [§2.1](../2-data-model/2.1-storage-layout/index.md)):

- `mempro init` — first-run scaffold; idempotent (see [§8.1](../8-bootstrap-and-lifecycle/8.1-first-run-scaffolding-mempro-init/index.md)).
- `mempro index rebuild` — regenerate derived files from authoritative files ([§2.1](../2-data-model/2.1-storage-layout/index.md)).
- `mempro index check` — validate derived files match authoritative files; non-zero on mismatch.
- `mempro verify` — full structural validation.
- `mempro version` — print version identity (the memory service's semver line, the store format
  revision this binary writes, the build id) plus the resolved store directory and the format
  revision found there. **Exempt from the format check** ([§9.1](../9-measurement-and-validation-regime/9.1-the-four-month-simulation-the-v0-5-0-acceptance-criterion/index.md)): never runs the format check, never
  runs startup recovery, never fails on a broken memory store. `mempro --version` prints the
  version lines in one-line short form only.
- `mempro archive list` / `mempro archive recover <thr_id>` — cold-storage archive ([§3.8.3](../3-core-algorithms/3.8-cold-storage/3.8.3-restore.md)).
- `mempro search <query>` — symbol/text search across the thread registry and threads (not built, ROADMAP A12).
- `mempro deps <thr_id>` — show threads referenced by anchors of the given thread (not built, ROADMAP A12).
- `mempro log <date|range>` — query the event log (not built, ROADMAP A12).

Persistent flags on every subcommand: `--home` (override the store directory for the invocation,
[§8.2.3](../8-bootstrap-and-lifecycle/8.2-configuration-sources-and-precedence/8.2.3-environment-variables.md)) and
`--allow-newer-home` (open a store directory whose on-disk format revision exceeds this binary's — [§9.1](../9-measurement-and-validation-regime/9.1-the-four-month-simulation-the-v0-5-0-acceptance-criterion/index.md); leaves a stderr
warning and a `system.home-format-override` event).
